# Loqui v0.1.1 release plan

## Goal

Publish the already-merged intuitive bilingual DMG installer as the immutable public
GitHub release `v0.1.1`, using the repository's protected manual Release Action.

## Constraints

- The release source must be a commit already merged into `main`.
- The stable version source is `info.version` in `build/config.yml`.
- macOS production and development plist metadata must be regenerated by
  `scripts/patch-plists.sh`; it must not be edited independently.
- `v0.1.1`, its tag, release, and release branch were absent before preparation.
- Existing tags and releases must never be moved, replaced, or deleted.
- Public assets must be exactly the canonical Apple Silicon DMG and its SHA-256 file.

## Approach comparison

| Approach | Complexity | Blast radius | Reversibility | Time to validate | Correctness / user risk |
| --- | --- | --- | --- | --- | --- |
| Edit only `build/config.yml` and let release packaging infer the rest | Low | High: plist metadata can remain stale | High before publication | Fast, but incomplete | High: filename and embedded version can disagree |
| Edit the source and plist files manually | Low | Medium: three synchronized edits | High before publication | Fast | Medium: manual drift bypasses the documented generator |
| Change the source, run `patch-plists.sh`, verify, merge, then dispatch Release | Low | Low: only canonical metadata and generated macOS outputs | High until the immutable release is published | Fast locally; notarization is slower | Low: follows the tested repository contract |

Chosen approach: use the documented generator and protected GitHub workflow. It has the
same small implementation surface as manual editing while retaining the repository's
version consistency and publication checks.

## Implementation units

1. Change `build/config.yml` from `0.1.0` to `0.1.1`.
2. Capture RED with `scripts/patch-plists.sh --check`: both macOS plist versions must be
   reported stale.
3. Run `scripts/patch-plists.sh` and capture GREEN with its check mode and the focused
   release-version tests.
4. Run the full repository check, review the exact diff, and ship the version bump through
   a normal PR into `main`.
5. Dispatch `.github/workflows/release.yml` from the merged `main` commit, approve the
   protected Environment when requested, and wait for the single run to finish.
6. Verify the public tag target, release state, asset names, checksum, and immutable source
   SHA. Update the README download metadata only after publication so it never links to a
   nonexistent release.

## Edge cases

- Abort before dispatch if `v0.1.1`, a matching draft, or its tag appears remotely.
- Do not dispatch from the version-bump branch or from a moving/non-merged commit.
- Do not start a replacement run while the serialized release run is pending approval.
- On an ambiguous workflow failure, inspect the tag and Release without deleting anything.
- Never log Apple credentials, identity hashes, notarization tokens, or unsanitized logs.

## Verification plan

- `scripts/patch-plists.sh --check` fails after the source bump and before generation.
- `scripts/patch-plists.sh` followed by `scripts/patch-plists.sh --check` passes.
- `scripts/tests/patch-plists-test.sh` and `scripts/tests/release-version-test.sh` pass.
- `CI=true ./scripts/task.sh check` passes on the exact proposed commit.
- The merged `main` SHA equals the release workflow's immutable preflight SHA.
- The workflow succeeds through signing, notarization, stapling, Gatekeeper, and publish.
- `v0.1.1` is public, non-draft, non-prerelease, targets that SHA, and contains exactly
  `Loqui-0.1.1-macos-arm64.dmg` plus `Loqui-0.1.1-macos-arm64.dmg.sha256`.
- The downloaded checksum file validates the published DMG.

## Acceptance criteria

- All three stable macOS version values are `0.1.1` on `main`.
- All standard workflow gates are green before the version-bump commit is pushed.
- One and only one `v0.1.1` release workflow is dispatched.
- The public release and tag satisfy every verification above without changing `v0.1.0`.
