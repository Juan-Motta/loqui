# Loqui v0.2.0 release plan

## Goal

Publish the Azure OpenAI transcription additions and movable-window fix already merged into
`main` as the immutable public GitHub release `v0.2.0`, using the repository's protected manual
Release Action.

## Constraints

- The release source must be a commit already merged into `main`.
- The stable version source is `info.version` in `build/config.yml`; `.forge-version` belongs to
  the workflow scaffold and is not product metadata.
- macOS production and development plist metadata must be regenerated by
  `scripts/patch-plists.sh`, never edited independently.
- `v0.2.0`, its tag, Release, and release branch were absent before preparation.
- Existing tags and Releases must never be moved, replaced, or deleted.
- Public assets must be exactly the canonical Apple Silicon DMG and its SHA-256 file.
- Only one Release workflow may be dispatched; an ambiguous failure is investigated read-only.

## Approach comparison

| Approach | Complexity | Blast radius | Reversibility | Time to validate | Correctness / user risk |
| --- | --- | --- | --- | --- | --- |
| Publish the current `0.1.1` metadata again | Low | High: collides with an immutable release | None after publication | Fast failure | Unacceptable: preflight must reject it |
| Publish the additions as patch `0.1.2` | Low | Low | High before publication | Normal | Medium: understates the new user-facing model capability |
| Bump the canonical source to `0.2.0`, regenerate metadata, merge, then dispatch Release | Low | Low | High until publication | Normal | **Selected:** minor version communicates new functionality and follows the tested pipeline |

## Implementation units

1. Change `build/config.yml` from `0.1.1` to `0.2.0`.
2. Capture RED with `scripts/patch-plists.sh --check`: both macOS plist versions must be stale.
3. Run `scripts/patch-plists.sh`, capture GREEN with check mode, and verify the resolved version and
   canonical DMG filename.
4. Run focused release tests and the full repository check, review the exact diff, and ship the
   metadata bump through a normal PR into `main`.
5. After the PR is merged, revalidate the exact `main` SHA and version, dispatch Release once, and
   wait for the protected Environment approval and workflow completion.
6. Verify the public tag target, release state, exact assets, downloaded checksum, and image validity.
7. Update README download metadata only after the Release exists, through a separate normal PR.

## Edge cases

- Abort before dispatch if `v0.2.0`, a matching draft, or its tag appears concurrently.
- Do not dispatch from the version-bump branch or from a moving/non-merged commit.
- Do not start a replacement run while the serialized release run is queued or awaiting approval.
- Never log Apple credentials, identity hashes, notarization tokens, or unsanitized notary logs.
- If publication becomes ambiguous, query the tag and Release without deleting or recreating them.

## Test plan

- RED: `scripts/patch-plists.sh --check` fails after only the canonical source changes.
- GREEN: generator plus check mode agree on `0.2.0` in both plist files.
- `scripts/release-version.sh` prints `0.2.0`; `--dmg-name` prints
  `Loqui-0.2.0-macos-arm64.dmg`.
- Focused plist, version, workflow, and publication contract tests pass.
- `CI=true ./scripts/task.sh check` passes on the exact proposed commit.
- Remote tag/Release absence is observed twice before dispatch.
- The workflow succeeds through build, signing, notarization, stapling, Gatekeeper, and publication.
- The downloaded checksum validates the published DMG and `hdiutil verify` reports it valid.

## Acceptance criteria

- All three stable macOS version values are `0.2.0` on merged `main`.
- The release branch contains only the intended metadata, plan, use-case, evidence, and changelog
  changes, with every standard ship gate green.
- Exactly one `v0.2.0` Release workflow is dispatched from the merged `main` SHA.
- `v0.2.0` is public, non-draft, non-prerelease, targets that SHA, and contains exactly
  `Loqui-0.2.0-macos-arm64.dmg` plus `Loqui-0.2.0-macos-arm64.dmg.sha256`.
- Existing `v0.1.0` and `v0.1.1` releases remain unchanged.
