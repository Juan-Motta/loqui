# Loqui v0.3.0 release plan

## Goal

Publish the automatic-update functionality already merged into `main` as the immutable public
GitHub release `v0.3.0`, using the repository's protected manual Release Action. The release must
include both the normal DMG installer and the signed application ZIP consumed by Loqui's updater.

## Constraints

- The release source must be a commit merged into `main`.
- The stable version source is `info.version` in `build/config.yml`; `.forge-version` is not product metadata.
- Production and development plist metadata must be regenerated with `scripts/patch-plists.sh`.
- Existing tags and Releases, including `v0.2.0`, must not be moved, replaced, or deleted.
- `v0.3.0` must be absent immediately before the release workflow is dispatched.
- The public release must contain exactly the canonical DMG, updater ZIP, DMG checksum, and `SHA256SUMS`.
- Only one new Release workflow may be dispatched; ambiguous outcomes are investigated read-only.
- No commit may land on `main` between the release merge and the workflow's successful completion.

## Approach comparison

| Approach | Complexity | Blast radius | Reversibility | Time to validate | Correctness / user risk |
| --- | --- | --- | --- | --- | --- |
| Re-run with `0.2.0` | Low | High: collides with an immutable tag | None after publication | Immediate failure | Unacceptable; preflight already rejected it |
| Publish as patch `0.2.1` | Low | Low | High before publication | Normal | Medium; understates a new user-facing update system |
| Bump to `0.3.0`, regenerate metadata, merge, then dispatch once | Low | Low | High until publication | Normal | **Selected:** communicates new functionality and uses the proven protected workflow |

## Implementation units

1. Change `build/config.yml` from `0.2.0` to `0.3.0`.
2. Capture RED with `scripts/patch-plists.sh --check`, proving both macOS plists are stale.
3. Run `scripts/patch-plists.sh`; capture GREEN and independently resolve the version, DMG name,
   and ZIP name twice.
4. Add the release changelog entry, CLI use cases, and sanitized E2E preparation report.
5. Run focused release contracts and the full repository check; review the exact diff.
6. Commit and push a normal release-preparation PR, merge it into `main`, and verify the exact
   merge SHA carries `0.3.0`.
7. Read `v0.3.0` tag and Release state twice, dispatch the Release workflow exactly once, record
   the unique run ID for the merged `main` SHA, and wait for that run's terminal completion.
8. Verify the public tag target, release flags, exact assets, checksums, ZIP contents, DMG validity,
   notarization staple, Gatekeeper acceptance, and the `/releases/latest` pointer using downloaded
   artifacts. Verify the DMG with its `.dmg.sha256` file and the ZIP with `SHA256SUMS`; extract the
   ZIP and validate the extracted `Loqui.app` signature, staple, and Gatekeeper assessment.
9. Update public download documentation after publication through a separate normal PR if the
   existing README links are version-specific.

## Edge cases

- Abort before dispatch if the tag or Release appears concurrently.
- Do not dispatch from the preparation branch or from an unmerged commit.
- Do not retry while a run is queued, active, awaiting approval, or has an ambiguous outcome.
- Abort and reassess if `main` moves after dispatch; the workflow intentionally rejects that state.
- Do not print signing credentials, identity hashes, notarization tokens, or raw notary logs.
- A failed run must be investigated before deciding whether a retry is safe.
- The previous failed run for `0.2.0` is historical evidence only and must not be deleted or rerun.

## Test plan

- RED: after changing only the canonical source, `scripts/patch-plists.sh --check` fails because both
  plist files still contain `0.2.0`.
- GREEN: generator plus check mode agree on `0.3.0` in both plist files.
- `scripts/release-version.sh` prints `0.3.0`; `--dmg-name` and `--zip-name` print canonical names.
- Focused plist, version, GitHub-release, updater-ZIP, workflow, and release-macos tests pass.
- `CI=true ./scripts/task.sh check` passes on the exact proposed tree.
- Two remote observations confirm `v0.3.0` is absent immediately before dispatch.
- The workflow succeeds through build, signing, notarization, stapling, Gatekeeper, and publication.
- The DMG validates against `*.dmg.sha256`; the ZIP validates against `SHA256SUMS` and contains
  exactly `Loqui.app`; both the mounted DMG app and ZIP-extracted app pass strict signature, stapler,
  and Gatekeeper checks, while the DMG itself passes `hdiutil verify`.

## Acceptance criteria

- All three stable macOS version values are `0.3.0` on merged `main`.
- The preparation PR contains only intended version metadata, release docs, evidence, and changelog changes.
- Exactly one new `v0.3.0` workflow is dispatched from the merged `main` SHA.
- `v0.3.0` is public, latest, non-draft, non-prerelease, and targets that merged SHA.
- Its exact assets are `Loqui-0.3.0-macos-arm64.dmg`,
  `Loqui-0.3.0-macos-arm64.dmg.sha256`, `Loqui-0.3.0-macos-arm64.zip`, and `SHA256SUMS`.
- Both downloaded artifacts match their published checksums and retain valid signed/notarized state.
- GitHub's `/releases/latest` endpoint resolves to `v0.3.0` and exposes the updater ZIP.
- Existing releases remain unchanged.
